# 经验沉淀（Lesson Harvest）

> **在哪做**：全局一致性审查的**最后一节**，交付收尾之后 —— 只有走完全程，才知道这次真正的代价是什么。
> **默认结论**：**本次无新增经验**。

## 🔴 立场（和「缺陷猎捕」正好相反，别套错）

缺陷猎捕那一维是「零发现 = 没做审查」；**本步反过来：「本次无新增经验」是最常见、也最健康的结论。**

每跑一次流程就产出一条"经验"，一年后规则集会变成没人读的垃圾场。而且 lessons 库与 `AGENTS.md`
**每个会话都要全量加载**，膨胀直接吃掉上下文预算，还会把真正重要的那几条稀释到看不见。

🔴 **宁可漏记一条，不可滥记一条。** 漏记的坑会再踩一次、那时再记，成本是一次；
滥记的条目会**永久**消耗此后每一次会话，且几乎不会有人回头删它。

## 判定链（四道，全过才算候选）

### ① 代价闸 —— 有没有**已经发生**的损失

有资格的，是本次流程中**实际发生过**的：

- 返工：写完又推翻重写
- 漏改：被 AI Review 的漏改反查逮到，或交付后才发现
- 门禁误判：该红没红，或红了但其实没问题
- 同一件事来回确认 ≥ 2 轮
- 验证做了白做：证据不成立、账号选错、测了个假环境、数字对错了源
- 工具 / 环境的坑：浏览器驱动、CDP、数据库、日志平台、构建工具上花了 ≥ 30 分钟才绕过去

🔴 **禁止预测性立法**：「以后可能会…」「保险起见加一条」不是经验，是臆想。**没有损失就没有条目。**

🔴 **一次损失 ≠ 一条新经验**：若根因是「没按既有的某条规则做」，那不是新经验，是**既有规则没被触发**。
该改的是那条规则的**触发时机 / 所在文件 / 措辞**，不是再加一条新的 —— 加新条只会让两条都更不容易被看见。

### ② 抹名测试 —— 先决定它属于哪一边

把这条经验里的**表名、字段名、模块名、平台名、路径、人名**全部抹掉，看还剩下什么：

| 抹掉后 | 归属 | 例 |
|---|---|---|
| 规则本身仍成立，换个项目也能用 | **本 skill**（落到哪个文件见 ③） | 「EXISTS 子查询必须含软删条件」——抹掉表名，规则照样成立 |
| 什么都不剩，规则**就是**那个具体事实 | 仓库 `AGENTS.md` | 「构建退出码不可信，要数日志 + 聚合测试报告」——抹掉就只剩本仓的构建配置 |
| 只在本次需求成立 | **不记录**，留在本次 docs 的 Spec / 自检报告里 | 「本次这个枚举字段存的是 dbName」——属需求事实，不是经验 |

落 `AGENTS.md` 时再分一次：

- **Learned User Preferences** —— 用户 / 产品的**决策与偏好**（"要做成什么样"）
- **Learned Workspace Facts** —— 环境、仓库、工具的**客观事实与坑**（"这里实际是怎样的"）

### ③ 落点选择 —— 进 skill 的，**不是一律丢进 lessons 库**

> 🔴 **一句话判据：执行到这条经验该生效的那一刻，AI 正在读哪个文件？就写进那个文件。**
>
> 浏览器操作的坑写进 lessons 库，等于把它放在**跑浏览器验证时不会打开的地方** —— 记了等于没记。

| 经验的性质 | 落点 |
|---|---|
| **浏览器 / 实机验证**的手法与坑（取证、异常态构造、并行、登录态、工具失效时的替代路径） | `references/browser-verification-playbook.md` |
| **缺陷检查项**（又一类"代码会在什么情况下错"） | `references/bug-hunting-checklist.md` 对应检查域 |
| **证据怎样才算数**（验收判据、盲审规则） | `references/evidence-acceptance.md` |
| **某一步的具体做法 / 约束 / 门控** | 该步的 `references/step-NN-*.md` |
| **产出物结构、归档、命名、目录约定** | `references/doc-output-and-context.md` |
| **跨步骤的原则**，或必须讲清「为什么」否则后人会当成多余而删掉的 | `references/lessons-learned.md`，并在相关步骤文件里留 `（见 LNN）` 锚点 |

**lessons 库与步骤文件的分工**：lessons 存**为什么 + 原则**，步骤文件存**这一步具体做什么**，用 `（见 LNN）` 互指。
这是既有文件一直在用的模式，不要打破。

🔴 **同一条经验不要写三处**：手法写进它该生效的那个文件；只有当它还需要「为什么」兜底时，
才在 lessons 补一条并用锚点互指。重复抄写的直接后果是改了一处忘了另一处 —— 本 skill 已经因此出过错。

### ④ 动作化 —— 能不能写成一条自检动作

必须能落成祈使句：**「在第 N 步做 X」/「禁止 Y」/「写 Z 之前先 grep W」**。

- ❌ 「下次要更仔细」「注意边界情况」「加强沟通」—— 无动作，丢弃
- ❌ 只描述现象、给不出处置的 —— 补不出处置就丢弃
- ✅ 判据：**把这一条交给一个没参与本次需求的人，他能照着做吗？**

### ⑤ 查重与并入

先搜四处：目标文件本身、本 skill 的 `lessons-learned.md`、`AGENTS.md` 的两个 Learned 节、项目 `CLAUDE.md`。

- **命中同一主题 → 并入既有条目，不新增编号 / 不新增条**（这是既定做法：实机验证那条被补充过四次，始终是同一个编号）
- 并入 lessons 时，在「最近更新」行注明「并入既有条目不新增编号」+ 来源单号
- 只有**确实是新主题**才申请新编号 / 新条

## 容量与淘汰（硬约束）

| 位置 | 上限 | 满了怎么办 |
|---|---|---|
| skill `lessons-learned.md` | **20 条**（同族按 1 条计） | 要新增，必须**同时提名一条淘汰或合并**，写明理由 |
| `AGENTS.md` → Learned User Preferences | **20 条** | 同上 |
| `AGENTS.md` → Learned Workspace Facts | **20 条** | 同上 |
| 其他 `references/*.md` | 不设硬上限 | 但须满足：①同一主题不得散落在多个文件 ②新增的每一条都要说得出「它在哪一步、什么时候被读到」 |

> 为什么只对前三者设硬上限：它们**每个会话都整份进上下文**；其余 reference 文件是执行到对应环节才按需读取，
> 膨胀代价局部可控 —— 但"局部"不等于没有，塞进一条永远不会被触发的检查项，同样是纯负担。

🔴 **禁止静默挤占**：不得为了塞进新条目而自行删除或改写既有条目。**淘汰提名一律交用户裁决。**

淘汰的正当理由只有三类，提名时必须指明是哪一类：

1. **已被更一般的条目覆盖** —— 它是另一条的特例
2. **依据已不存在** —— 所依赖的代码 / 表 / 工具 / 流程随重构消失了
3. **已被自动化门禁取代** —— 现在有脚本或测试每次都会查，不必再靠人记

## 🔴 门控：提名 → 用户确认 → 才写入（阻塞）

**本步只产出提名表，不直接改任何文件。**

> 之所以阻塞：skill 与 `AGENTS.md` 是 AI **自己后续要遵守的规则**。
> 让它无监督地改写自己的规则，一条错的经验会被当成铁律一路传下去，且没有任何环节会质疑它
> —— 后续每个会话都把它当既定前提读进来。skill 还要分发到多个 agent 工具目录，改一处等于同时改所有。
> **规则集的增与删，必须有人签字。**

提名表格式：

```
| # | 候选经验（一句话） | 代价（实际发生了什么） | 抹名后 | 建议落点（到文件） | 查重结果 | 动作化后的规则 |
|---|---|---|---|---|---|---|
| 1 | …… | 某条 AC 返工两轮 | 规则仍成立 | step-NN-*.md（该步约束） | 与既有条目不同主题 | 写 XML 前先 grep 实际表名 |
| 2 | …… | 取证白做 40min | 规则仍成立 | browser-verification-playbook.md | 该文件已有相近段落 → 并入 | 截图前先裁剪放大到判定点 |
| 3 | …… | 查日志白查 40min | 什么都不剩 | AGENTS.md / Workspace Facts | 无 | 查缓存前先确认 db 号 |
```

容量已满时，同表追加一行：

```
淘汰提名：建议淘汰「……」，理由类别：①/②/③ + 具体说明
```

**没有候选时**：写「本次无新增经验」，并**列出各道判定的结论**——
通常是 ① 本次没有发生实际损失，或 ⑤ 想到的都已被既有条目覆盖。
**一句话的「无」与没做本步无法区分。**

用户确认后，才执行下面的写入。

## 写入规范（获确认后执行）

**`references/lessons-learned.md`**

- **新增**：`### LNN. 标题（第N步）`，正文含 **现象 / 根因 / 规则 / 自检动作**；
  同步更新「条目计数」的当前数、「最近更新」行（日期 + 来源单号）、文末索引表（含「来源」列）
- **并入**：直接补进既有条目正文，**不动编号**，只更新「最近更新」行
- 🔴 **两个 workflow 的 lessons 各自独立编号**，同一条经验在两边编号不同。
  往另一个 skill 同步时必须**重新查号**，禁止直接复制 `LNN` —— 这类错已实际发生过两次

**其他 `references/*.md`**

- 写进**既有小节**，不要为一条经验新开一节
- 保持该文件原有的体例（清单文件就写成一条检查项，playbook 就写成一段手法 + 适用条件）
- 🔴 **两个 workflow 的步号不同**：含 `StepN` 的句子同步到另一个 skill 时必须重新对号

**仓库 `AGENTS.md`**

- 一行一条，**句首点明触发场景**（"查缓存时…""跨仓改契约时…"），让它在对的时候被想起来
- 带上来源（单号或日期），便于日后判断是否已过期
- 写进两个 Learned 节之一，不要新开小节

**写完必做**

- 🔴 跑 `python scripts/validate_step.py --self-check`，确认 lessons 引用、步号引用、计数行全部自洽
- 🔴 skill 改完要**分发到其他 agent 工具目录**（skill `distribute-agent-skills`），否则只有当前这个工具看得到，而且不报错
