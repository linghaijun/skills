# 第九步：逐条编码（仅业务代码）

**输入**：Step1~8 全部产出物（尤其 tasks.md）

**动作**：【核心防错】拿 tasks.md 一条一条喂给 AI 逐个击破，**禁止一次性写完所有代码**。

**约束**：
- 编码提示词："针对 tasks.md 任务 N.x（对应 Checklist AC-NN），结合 Step5 DDL、Step6 接口定义、Step7 测试指标，编写业务代码。"
- **只写业务代码(Controller/Service/Mapper/DTO)，禁止写单元测试**
- 每完成一个任务将 tasks.md 中 `- [ ]` 改为 `- [x]`
- **按依赖顺序**：被依赖的先做，无法确定时向用户确认
- 🔴 **按 Step4 选定的落点改，禁止就地打补丁**：Step4「改动落点选择」定了在共享层改的就改共享层，不得图省事在当前调用点复制一份逻辑绕过去。确需偏离时**先说明理由并回写 Step4**，不要静默改变落点
- 🔴 **每完成一条任务顺手核对影响面清单**：Step4 清单中与本任务同主题、判定"需改"的同类点是否都已覆盖；编码中 Grep 时新撞见的同类点必须补进清单，**不得只改手头这一处就勾 `- [x]`**
- 🔴 **有意改变既有行为时，当场标记受影响的 AC（L18）**：本次若决定「改掉原来的做法」（含为修缺陷而改），立刻找出描述旧行为的 AC 并记进待改写清单 —— AC 不会因为实现变了就自动过期报错，拖到第十二步才发现就是返工
- 🔴 **日志按「将来怎么查」写（见 L16）**：日志的读者是半年后的人和 AI。每条业务日志带**可定位业务键**；**兜底 / 降级分支禁止把不同根因塌缩成同一句固定文案**（必须带出最内层 cause）；异常作为参数传 logger，禁 `+ e.getMessage()`；永不打印凭据。否则故障时无法区分「永久失败需人工」与「瞬时抖动会自愈」
- 🔴 **端点完成时做一次契约自测（30 秒，别等到 10.4）**：新增/改动的端点各打一次（curl，或 `javascript_tool` 在已登录页面内 `fetch`），确认**实际返回结构与 Step6 契约逐字段一致**（字段名、类型、枚举、分页结构）。不一致立刻改，**不要把契约偏差留到联调**

**复用点强制落地**：tasks.md 标注"复用 XXX"的任务必须直接调用既有方法，禁止新建。签名不匹配时优先扩展既有方法。

**非功能需求落地**：逐条对照映射表中"落点=代码"的行：
- 事务：跨表写/跨 Service 标注 `@Transactional`
- 乐观锁：UPDATE WHERE 含 `version = #{version}`，Service 捕获 `OptimisticLockException`
- 缓存：`@Cacheable`/Redis，TTL 与映射表一致
- 并发控制：分布式锁(Redisson)/synchronized
- 权限：`@PreAuthorize` 按 API 文档标注
- **未落地即未完成**，不得勾选 `- [x]`

**禁止 git 提交（强制）**：只写入工作区，禁 `git add/commit`。提交统一在 Step11 AI Review 通过+人工审批后进行。

**产出物**：生产代码（按项目既有结构放置）

**→门控**：🟡 **通知式** —— 汇报代码文件清单 + tasks.md 勾选进度 → 直接进入 Step10。

> 🟡 **通知式门控**：产出物落盘 → 跑 `validate_step.py`（FAIL 必须修到通过）→ **一句话汇报**（路径 + 校验结果 + 本步做的关键决策）→ **不等待，直接进入下一步**。
> 用户随时可提异议；收到异议必须**回退重做本步及其下游**，不得争辩已经过了。
> 之所以不阻塞：本步产出物是文档/任务清单，**改起来几分钟且未产生不可逆后果**；把人的注意力省给真正拦不可逆事项的那几道门。
