# 第四步：技术方案与实现计划

**输入**：Checklist + 技术栈架构说明

**动作**：评估技术可行性，梳理实现步骤，**强制识别可复用能力**。

**约束**：
- **影响面清单（强制，防漏改）**：不只列"要改哪些"，更要列"**还有哪些是同一件事**"并逐项判定：

```
| # | 同类点(文件:行/端点) | 属于哪类(读取口径/其他入口/其他平台/写入侧/枚举副本/其他 XML) | 判定 | 理由或对应 AC-NN |
|---|---|---|---|---|
| 1 | AssetController#export:88 | 同一数据的其他读取口径 | 需改 | 与 list 共用过滤，AC-12 |
| 2 | WalmartAssetHandler:40 | 其他 productLine | 不需改 | 该平台无此字段（用户已确认） |
```

  - 候选来源：Step1「影响面反查」的清单 + 本步 Grep 复核（六类：读取口径 / 其他入口 / 其他平台 / 读写两侧 / 枚举副本 / 其他 Mapper XML）
  - **判定为"需改"的必须有对应 `AC-NN`**，没有就回 Step3 补条目；判定"不需改"必须写理由
  - **存在未判定项 → 本步未完成，禁止进入 Step5**
  - 清单同时是 Step11 维度 A3 / Step12 的漏改反查基准

- **改动落点选择（强制，禁止就地打补丁）**：影响面清单里判定"需改"的点 **≥2 处**时，必须先评估能否在**公共层改一处**解决（公共 Service / 枚举单一真源 / BaseMapper / 拦截器 / AOP），再决定落点：

```
| 改动主题 | 同类点数 | 候选落点 | 选定落点 | 为什么是这一层 | 该层其他调用方影响 |
|---|---|---|---|---|---|
| 过滤条件注入权限 | 4 | ①各 Handler 各加一次 ②统一在查询组装处 | 统一组装处 | 4 处口径必须一致(L13)，分散必漂移 | 另有 2 个调用方，已确认同样需要 |
```

  - **≥2 处 → 上提共享层**；**=1 处 → 就地改**，不得为"将来可能复用"提前抽象
  - 🔴 **上提改动 = 影响面重新扫一遍**：改了共享层就等于改了它的**全部**调用方，必须重新 Grep 该层被谁调用，逐个判定是否受影响，结果补回影响面清单
  - 已有枚举/常量/公共方法的，直接改真源，**禁止新增并行副本**（见 L6）

- 🔴 **分层落点（架构边界，机械门禁会验）**：除了"改哪一层共享/就地"，还要声明**落在哪一分层**，并对照项目既有分层写明有无跨层：

```
| 改动主题 | 分层落点 | 是否跨层 | 说明 |
|---|---|---|---|
| 素材列表加筛选 | Controller 收参 → Handler 编排 → Service 查询 → Mapper | 否 | 按既有分层 |
| 导出复用查询 | 复用 AssetQueryService | 否 | 不在 Controller 里拼 SQL |
```

  - 本项目的分层边界由 **ArchUnit 机械门禁**守（`creative-management-api` 的 `ArchitectureTest`，3 条规则全部 `freeze()` 棘轮、基线已提交进仓）：
    - `controllerMustNotDependOnMapper` —— **Controller 不得直连 Mapper**，必须经 Manager/Handler/Service；该规则**存量 0 违规**，新增一处立刻红
    - `noFieldInjection` —— 新类一律**构造器注入**，禁止把 `@Autowired`/`@Resource` 打在字段上
    - `utilsMustNotDependOnSpring` —— `utils` 包保持纯静态工具，不依赖 Spring 容器
  - 🔴 **棘轮的含义：这三条失败 = 你新增了违规**（存量已冻结不会报）。**禁止把新违规写进 freeze 基线**来让它变绿 —— 那是把门禁反向用成了许可证
  - 设计阶段就想清楚落在哪层，比编码后被门禁拦下再返工便宜

- 🔴 **回归风险候选（强制，供 Step7 产出回归清单）**：影响面清单里**判定"不需改"但走同一段共享代码**的点，以及**上提到共享层后被动受影响的其他调用方**，全部列为回归候选 —— **"不需改" ≠ "不会受影响"**：

```
| 受影响的既有功能 | 因为改了什么 | 期望不变的行为 | 回归验证方式 |
|---|---|---|---|
| Walmart 素材列表 | 共用 AssetQueryBuilder 注入了权限 | 返回条数与改动前一致 | 切 Walmart 账号跑列表比对 |
```

  - 本表是 Step7《回归验证清单》的输入，**不得为空**（确实零回归风险时写明"无共享代码改动"并说明依据）
- **技术盲区**：识别并发/大数据量/三方 API 超时风险
- **依赖与复用识别（强制动作）**：写新代码前必须 Search/Grep 现有代码库：
  - 可复用的 Service/方法（文件位置）
  - 可复用的 DTO/常量/枚举
  - 外部依赖（Feign/MQ/缓存/三方 API）
  - **不重复造轮子**：已判定可复用的直接调既有方法
  - **口径澄清**："强制"的是识别动作和不重复造轮子；复用本身是"优先"，不适配可不复用，但须在复用清单写明理由
- **非功能需求落地映射（强制）**：Step1 收集的非功能需求必须逐条映射到具体技术落点：

```
| 非功能需求 | 落地技术方案 | 落点位置 | 验证方式 |
|---|---|---|---|
| 查询<1s | group_id 联合索引 | ddl.sql | 测试矩阵+10.3自检 |
| 500 QPS | Redis 缓存 5min | XxxServiceImpl | 11步 D 维度检查 |
| 跨表原子性 | @Transactional | ShareServiceImpl | 10.3+11步 D 维度 |
```
- 未映射的非功能需求 → 未完成本步，禁止进入 Step5。落点必须可被后续步骤追溯验证

**产出物**：`.../Step 4-技术设计与实现方案文档.md`，含：
1. 改动点清单
2. **复用点清单**（可复用 Service/DTO/常量 + 位置 + 方式）
3. **非功能需求落地映射表**
4. 核心业务伪代码
5. 潜在风险提示

**→门控**：🟡 **通知式** —— 落盘 → 汇报路径 + 关键决策（复用了什么、落点选在哪层、影响面清单结论）→ 直接进入 Step5。

> 🟡 **通知式门控**：产出物落盘 → 跑 `validate_step.py`（FAIL 必须修到通过）→ **一句话汇报**（路径 + 校验结果 + 本步做的关键决策）→ **不等待，直接进入下一步**。
> 用户随时可提异议；收到异议必须**回退重做本步及其下游**，不得争辩已经过了。
> 之所以不阻塞：本步产出物是文档/任务清单，**改起来几分钟且未产生不可逆后果**；把人的注意力省给真正拦不可逆事项的那几道门。
