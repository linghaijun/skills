# 速查表 4：国际化（i18n）

## 使用规则（强制）

- **模板和脚本里统一裸用全局 `$t("key")`**。`$t` 由 `@pacvue/frame` 的 `i18nEntry.js` 定义并挂到 `window.$t`（i18n 实例 `globalInjection: true`），因此无需任何 import。
- **禁止 `useI18n()`**、禁止自己 `createI18n`、禁止 `import { $t } from "vue-i18n"`。
- 带参数插值：`$t("key", { n: 1 })`；数组批量翻译用 `commonJS.PacvueTranslateT`。
- 页面上出现 `{122}xxx` 前缀 = 该 key 缺翻译（missing handler 特征），去翻译仓库补 key，不要在代码里兜底拼字符串。

## 翻译文件结构

| 包 | 内容 | 说明 |
|----|------|------|
| `packages/langsCommon/Common/` | `en / ja / zh_CN` 的 `.js` + `.json` | 各平台共用文案 |
| `packages/langs/<平台分支>/` | 同上（如 `AmazonSearch/`、`Commerce/`、`Dsp/`） | 平台专属文案 |

- 这两个包是 **git subtree**，源仓库 `Pacvue/localization`，按平台分支管理（`pacvue.config.json` 的 `subtree.langs.branch`）。`pnpm initP` 时自动拉取/更新，**不要手改本地 `en.js` 等大文件**——新增/修改文案走 lokalise / localization 仓库流程。
- key 命名存在 `amskey123` 这类无语义编号 key 与语义 key（如 `Profile`）混用。
- locale 存储：`localStorage.locale`（EN/ZH/JA），翻译内容缓存在 IndexedDB（localForage 实例 `PacvueLocale`）。
- 本地开发建议装 VSCode **i18n Ally** 插件，`i18n-ally.localesPaths` 指向对应平台目录（见 `packages/langsCommon/README.md`）。

## 相关 i18n skill（按需求分工，不要混用）

| 需求 | 用哪个 skill | 说明 |
|------|-------------|------|
| 查单条翻译 / 某段英文文案对应的 key / 查 `amskey` 等 key 内容 | **`i18n-lookup`** | lokalise 查询，精确 key 匹配；写 `$t("整句英文")` 前先用它核实该英文是否作为字面 key 存在 |
| 审查整页 / 整模块「哪些用户可见文案没国际化」、要覆盖率 / 待国际化清单 | **`pacvue-i18n-audit`** | 两层核查：① 逐文件找漏包 `$t()` 的裸字符串；② 已包的字面 key 是否真命中翻译包（禁止用英文 value 反查判定有无）。产出「模块→文件→行号」清单 |

> 规则同源：写文案时**禁止**把整句英文当 key 直接传 `$t()`——Pacvue 翻译包大量是「技术 key → 英文文案」映射，key 名与显示文本经常不同，直传英文会查不到、触发 missing 兜底。判断「是否已有翻译」只能查字面 key 是否存在，不能用英文串在文件里出现这种宽松匹配。
