# Figma 设计稿缓存（UI 读取与对照）

> **时机**：用户给出 Figma 链接时立刻缓存（通常在 Step1 / Step7 / Step10 前端编码前）；设计稿更新后重跑。
> **产出**：需求目录 `figma/<节点>/{screenshot.png, design.md, node.json}` + 总索引 `figma/README.md`。
> **脚本**：`scripts/figma_cache.py`。

## 一、为什么要缓存，而不是每次现看

- 截图只给观感，**色值、间距、圆角、字号、auto-layout 规则**要从节点数据里取；凭截图目测写样式，偏差是必然的。
- 设计稿一页往往有十几个状态帧（初始 / 分析中 / 已选中 / 生成中…），编码要反复对照，**每次现调接口既慢又占上下文**。
- 缓存落在需求目录，Step7 设计、Step10 编码、Step11 验证、Step13 审查都引用同一份，**不会出现「两个步骤看的不是同一版稿」**。

## 二、怎么取

```bash
python scripts/figma_cache.py --dir "docs/develop/<需求目录>" --urls "<链接1>" "<链接2>" ...
python scripts/figma_cache.py --dir "..." --urls-file links.txt   # 链接多时一行一个
python scripts/figma_cache.py --dir "..." --refresh              # 设计稿更新后按已有节点重拉
```

- **令牌**：环境变量 `FIGMA_API_KEY`（或 `FIGMA_TOKEN`）。脚本只读环境变量，**不打印、不写进任何文件**。
- **先查令牌再说「读不了」**：figma MCP 插件常处于 `needs_auth`，但只要环境变量里有令牌就直接走 REST API，**不要先让用户去 /mcp 授权**。环境变量也没有时，才请用户提供令牌或授权插件。
- 链接里 `node-id=13535-44175` 即节点；同一节点出现多次只读一次；不同文件的链接可以混在一起给。

## 三、取完之后必须做的（脚本只负责下载，下面三件由 AI 完成）

1. **逐张看截图，填索引的「区域」「对应 AC」两列**：写清是哪个页面、哪个区域、什么状态（如「PD 分析中：Product 下方灰底进度条，此时没有输入框」），并对上 AC 编号。重跑脚本时这两列会保留。
2. **填「关键样式」表**：从 `design.md`（或需要精确值时查 `node.json`）提取要实现的元素规格——字段标题、按钮 / 选项的未选与选中态、进度条、卡片、角标——色值、尺寸、圆角、字号、间距。**编码时样式以这张表为准，不凭记忆、不凭截图目测。**
3. **填「与文档 / 已写代码的差异」表，逐条交用户裁决**：设计稿与 PRD、标注图、Checklist、已写代码不一致的地方（文案、显示时机、布局、命名），写清两边各是什么、建议取哪个。用户定了之后：
   - 记进问答记录（新 Q，状态「已定」）与决策记录；
   - 同步受影响的 AC（Checklist → 重新生成 Jira 纯净版 → 证据 case.md）、Step7、前端矩阵；
   - 已写代码按结论改。

## 四、读稿时容易踩的坑

| 现象 | 处理 |
|---|---|
| 同一文件里混着新旧两版帧（标签、Tab 名还是旧的） | 以多数整页帧 + 用户最新标注为准；旧帧只当状态示意，在索引「区域」里注明「旧稿示意」 |
| 标注图（评审批注）与设计稿用词不同（如标注写「Resize」，稿上是「Image Resize」） | 列进差异表问用户，不要自己挑一个 |
| 设计稿里某字段只在某状态出现（如未选来源时不显示输入框） | 这是交互规则不是视觉细节：写进 Step7 交互规则，并检查 AC 是否描述了相反的行为 |
| 网格不是等分（如首行 3 列、之后每行 2 列） | 看 auto-layout 的列宽而不是数截图里的格子，写进关键样式表 |
| 只看了截图就写样式 | 回到 `design.md` 查对应节点的 fill / stroke / radius / font，样式表里写数值 |

## 五、与其他规则的关系

- **来源优先级**：设计稿属于「UI 截图 / 设计稿」，优先级高于 PRD、低于用户最新明确指令（见 `step-01-requirements-qa.md`「信息来源优先级」）。冲突必须显式记录并复述确认，禁止静默取舍。
- **证据**：设计稿缓存是需求输入，不是验证证据；页面验证仍按 `browser-verification-playbook.md` 实测留证。
