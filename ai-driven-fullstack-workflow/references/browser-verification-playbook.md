## 最关键的红线（细则在括号里的章节，这里只负责让你想起来）

1. 🔴 **默认只读**；「账号可用」≠「写操作被授权」，**每一次**写 / 删都带「动作 + 账号 + 对象 + 会写什么 + 可逆吗 + 影响面」单独问，授权不跨条目、不跨会话（§0）
2. 🔴 **Agent 不代输、不读取任何凭据**；未登录走固定交接协议，等用户明确说登好了再继续（§2.2）
3. 🔴 **动手前先读脚本分层**（cdp `SCRIPTS.md` → `projects/<项目>/` + `PAGE-NOTES.md`），禁止现写探针；**先扒清页面背后的库并做数据指纹比对**，对不上就停（§1）
4. 🔴 **需要交互（点筛选 / 切页签 / 悬停 / 人工登录）一律自拉 Chrome + CDP**；`--user-data-dir` 固定且独立；**多账号 = 独立端口 + 独立 `--user-data-dir`**（同一 Chrome 的标签共享 cookie，只换端口等于白做）（§2、§2.1、§2.4）
5. 🔴 **点之前核对落点、驱动前确认页面可见**，别按文本点筛选项（§3）
6. 🔴 **开测前逐 AC 写断言清单，按 §4.0 的 12 条自检**；判定截图必须「裁剪 + 放大 + 框边写字」且自己打开看过，标注不用黑色（§4.0、§4.1）
7. 🔴 **构造态（内存补丁 / CDP Fetch）用完即清**，结论标「构造」，不能单独支撑「通过」（§4.2）
8. 🔴 **否定型 AC 必须用受限普通账号**，超管跑 = 假绿灯；默认只用内部账号（§8、§10）
9. 🔴 **默认并行，开测前先出并行分组表**；写操作 / 有依赖的 AC 串行；每次工具调用显式带自己的 `tabId`；CDP 脚本一律 **`CDP_TARGET=<targetId>` 锁窗口**，不用 `--index`（§12、§12.0）
10. 🔴 **开始 `claim`、收尾 `finish`**，一条 AC 同时只能一个会话占用，只用自己登记的窗口（§12.2、§12.3）
11. 🔴 **改代码当场 `invalidate` 受影响 AC；并行轮开始后冻结代码**，只修阻塞缺陷（§12.4）
12. 🔴 **证据当场采齐、随走随落**；终验逐条给结论，`豁免` 只限用户明确放行（§11、§12.5）
13. 🔴 **数据核对只读 SQL，重查询同时 ≤2**（慢查询会拖垮共享 MCP 服务）；**禁止改 SQL 让它对上**（`data-reconciliation.md`）
14. 🔴 **验证全程禁 `git add/commit`**，子 agent brief 里同样写明（提交只在全局一致性审查通过后）
