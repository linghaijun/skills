## 4. 取证：别把响应体倒进上下文

抓包工具按 requestId 返回的是**完整响应体**，列表类接口一条就几千 token。
**在页面内挂只读钩子，只返回归类结果**：`fetch` 与 `XMLHttpRequest` **都要挂**
（不同组件用的不是同一个），用 `res.clone()` 避免把 body 读掉导致页面解析失败。

钩子只读**响应**，不碰请求头、不碰凭据。
想调接口就**驱动 UI 让应用自己发**，别自己拼请求（读 token 存储会被安全策略拦，也不该绕）。

### 4.0 🔴 首测即过：开测前逐 AC 自检（照着验收员的标准测，别等它退回）

> 实测：一次证据验收 53 条退回 32 条（缺证 11 / 证据不实 21），**修复回路比首测还费时**。
> 退回原因几乎都能在开测前避免。下面每条都是「测之前就要做的动作」，对应 `evidence-acceptance.md` 的 C1~C7。

**开测前（写进 `case.md`）**：把 Then 拆成**一行一个断言**，每个断言写清「用哪张标注图的第几号框 + 哪个机器证据字段」证明。写不出来 = 还没想清楚怎么测，别开浏览器。

| # | 动作 | 不做会被退的样子（实例） | 对应 |
|---|---|---|---|
| 1 | **Given 的前置也要有证据**：「首次进入 / 未配置」→ `fresh-entry.mjs` 输出 + 进入后存储 key 仍为空；「离开再进入」→ 导航离开 + **完整重载**回来，不是同页切 tab；「周期内无投放」→ 接口 `totalCount=0`；「平台不支持」→ 行模型字段为 `null` | AC-09/19：没证明是首次进入；AC-13/21：只是内存态，key 是 null | C1 |

### 4.1 截图证据要让人一眼看出判定点

整页截图 ≠ 证据。判定点往往只占画面一小条（字段区、某个单元格、某个 ID），
审阅的人看到一张满屏图，不知道该看哪里，等于没留证。

- 🔴 **强制（范围：凡是作为 AC 判定依据的截图）**：每张都要配一张「裁剪 + 放大 + 标注」版 ——
  裁到判定区域，放大到文字清晰（约 2×），用框圈出每个判定点，**每个框边必须贴「编号 + 文字说明」**，
  图顶再写一行总说明（这条 AC 验的是什么）。
  **缺标注版的判定截图 = 证据不完整**，证据归档门禁判不通过。
  🔴 **用户硬要求：证据截图一定要有标注**（裁剪 + 放大 + 框住判定点 + 框边写文字，存成 `AC-NN-序号-<中文判定点>-标注.png`，文件名内容一律中文，命名见 `doc-output-and-context.md`「证据文件命名」）。没有机器校验，收尾前自己逐张打开确认。
- 🔴 **框坐标从页面导出，且能证明与截图同帧**：截图**前后各导一次** rects（× dpr），`cmp` 逐字节一致才用；
  两份 rects + 标注用的裁剪坐标 + 生成脚本一起存进 `evidence/` / `script/`。只存一份或只存在 scratchpad 里，验收无法证明「同帧」（实测被验收追问后补存）
- 🔴 **瞬态元素（toast / 消息条 / 滑入动画 / 抽屉）先等稳定再截**：轮询它的 rects 到**连续两次逐字节一致**再截，截后再导一次核对；不一致就在它可见期内重拍（cdp skill `sconn.mjs` 的 `waitStable` / `snapSame`）。只做「前后各导一次」拦不住正在滑入的提示框（实测有 AC 第 4 轮验收因此退回）
- 🔴 **用录屏 / screencast 帧当关键帧时，按帧内画面选，不按时间戳选**：帧比 DOM 晚一拍，DOM 读到 100% 的那一刻对应帧里进度条可能才画到一部分。先量像素（cdp skill `barw.py` 量填充宽度、或裁剪看文字）再选，选完用 Read 打开确认（实测第 4 轮 4 张标「100%」的图实为 15%~78%）
- 🔴 **真实客户数据的下载文件「验完删」之前，先落可复算产物**：解析脚本进 `script/`；去标识化逐行结果（行号、类型、判定字段是否成立、文字哈希、每行每列图片数）+ 请求元数据 + md5 进 `evidence/`。
  只留一段解析摘要 = 无法复核，验收判缺证（实测因此重新导出一次）。计数对不上（如图片总数差 N）要逐行落到具体行，别只报总数
  （纯过程记录截图不在此列，但它本来也不能单独用来判定）
- 原始整页图**保留**（证明上下文、页面与数据来源），标注图另存；文件名用中文、原图以 `-原图` 结尾、标注图以 `-标注` 结尾、同一序号成对（如 `AC-08-01-第1页广告名称列只显示Ad名称-标注.png`），
  并在 `RESULT.md` 写明两张图各证明什么
- 有修复前后对照的，两张图并列登记（修复前 / 修复后），别只留修复后
- 🔴 **只有框和序号不算标注**：序号逼着复核者在图和说明带之间来回对照，和"不知道该看哪里"只差一步。
  **文字要贴在框边**，写这个框里该看到什么（「Status 应为 Archived」「总条数应为 21」）
- 💡 **建议：标注文字用中文**（不进门禁）：框边说明、图顶总说明、拼图面板标签都写中文（如「进度条停在 100% 约 0.5 秒」）；`AC-NN`、jobId、字段名、接口路径和页面上的英文 UI 文案按原样保留。细则见 `doc-output-and-context.md`「建议：证据文档用中文」。
- 🔴 **标注一律不用黑色（含深灰）**：框线、编号、框边说明底色、图顶说明带都用醒目色，**默认红色**；
  一张图里要区分多组判定点时可换蓝 / 橙 / 绿 / 洋红，但不要用黑或深灰 —— 截图本身大量是黑字、深色控件，
  黑色标注和页面内容混在一起，没有区分度。
  `annotate.py` 的 `--color` 传深色会直接报错退出；自己写 PIL 时同样遵守
- 标注文字只写**看得见的事实或期望**（「ID 常显不截断」），不写推断、不写结论
- 🔴 **一条说明写不下会被静默截断，标注图直接作废**。这个失败**不报错**：
  命令跑完了、图也生成了，只有**亲眼打开看**才发现第二行被切掉半句。
  三条一起用：
  ①**一条说明只讲一个判定点**，超过约 20 个汉字就该拆成两条（而不是写成一长句）；
  ②真的长就**显式断行**（脚本的 `\n`），别指望它自己变短；
  ③用**会自动折行并在折行时告警**的工具，不要手搓 —— 手写的画框代码通常既不折行也不提醒
- 🔴 **标注图必须自己打开看过才算证据**：要求别人"一眼看出"，自己得先看一眼。
  至少确认三件事：**文字完整没被切**、**标签没压住判定内容本身**、**编号与说明对得上**。
  这一步不能省 —— 它是上面那条静默失败唯一的拦截点
- 落盘前自问：**不看我的解释，别人能从这张图里指出通过的依据吗？** 不能就重做

**怎么做（从上往下选，保证这道门禁永远有可满足的路径）**：

| 优先 | 做法 | 适用 |
|---|---|---|
| **1** | **跑现成的标注脚本**（cdp skill `scripts/annotate-rects.py`（默认：页面导出的 rects + 裁剪区 → 框边写字）或 `scripts/annotate.py`（手给裁剪坐标）；🔴 不要用 `annotate-legend.py`（图例版不合本节「框边必须写字」，实测第 5 轮验收因此退回两条 AC）：一条命令完成裁剪 + 放大 + 画框 + 框边「编号 + 文字说明」+ 顶部总说明带，**文字过长自动折行并打印告警** | 默认 |
| **2** | **自己写 PIL**：`crop` + `resize(LANCZOS)` + `ImageDraw.rectangle/text`，中文字体用系统字体（如 `C:/Windows/Fonts/msyh.ttc`）。🔴 自己写就要自己补上**折行、边界回拉、折行告警**，否则必然踩上面那条静默截断 | 项目没有现成脚本 |
| **3** | **`computer{action:"zoom", region}` 出裁剪放大图** + 在 `RESULT.md` 逐条写「编号 → 期望 → 它在图中的什么位置」 | 环境里没有 Pillow（画不了框，文字说明一个都不能少） |
| **4** | 证据是**录屏**时：不画框，改为在 `RESULT.md` 标**时间点**（`00:12 → 期望 X`） | 录屏类证据 |

> 用到 3 或 4 时，在 `RESULT.md` 注明**为什么降级**（和证据形式降级同一套记法）。

🔴 **坐标两件事**：标注坐标按**截图像素**算，不是页面 CSS 像素；
CDP / 高 DPI 截图有 DPR（如 1.2、2）时，CSS 坐标要**乘 DPR** 才对得上。

> 也可以在页面里注入高亮（给元素加红框）再截图，但那是**页面内存补丁**，
> 必须走 §4.2 的纪律：用完整页刷新清除，且**结论不能建立在补丁在场时拿到的数据上**。

### 4.2 页面内存补丁：用完即清，下结论前先确认已失效

为构造「空数据 / 字段缺失 / 图片失败」等真实数据里没有的场景，常在页面里改写 `XMLHttpRequest`
或 `fetch` 的响应。补丁**挂在页面内存里，不会自己消失**，一直作用到整页刷新为止。

- 🔴 **一个补丁只服务一个场景**：构造完、截完图，**立即整页刷新**清掉，再做下一件事
- 补丁置一个全局标记（如 `window.__patchedXxx = true`），补丁命中时记 `window.__patchHit`
- 🔴 **任何一条「真实数据」结论落盘前，先读标记确认补丁不在**；标记还在，这条结论就是构造出来的
- 补丁在场时拿到的结果，结论里**必须写「构造（内存补丁）」**，不得写成真实数据
- 补丁第一次「没命中」不代表它没装上：组件可能读了缓存，下一次请求才命中。**没命中就先刷新清掉**，换别的方法，别让它留着等下一次请求
- 浏览器实机报告的「遗留脏数据」表里，要登记「页面内存补丁 → 整页刷新 → 已复核标记为 false」
- 🔴 **改写接口响应来构造（首帧 / 失败分支 / 超时 / 空数据）优先用 CDP Fetch 拦截，别各写一套页面补丁**：cdp skill `fetch-stub.mjs`（`Fetch.enable` 按 URL 模式锁死范围 → `fulfillRequest` / `failRequest`）。三件事缺一不可：①开拦截后先自检一次（伪请求拿到的确实是构造体）；②证据一律标「**构造（CDP Fetch）**」，不能单独支撑「通过」；③结束 `Fetch.disable` + 整页 reload + **读回一次真实响应确认已失效**，读回结果作为证据留档。实测：首帧、失败分支、超时构造各组各写一套补丁，收尾与标注口径不一被退回。
