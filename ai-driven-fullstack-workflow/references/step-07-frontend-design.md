## 🔴 状态归属判定（组件间 bug 的第一来源）

> 前端最难查的 bug 大多不是"渲染错了"，而是**同一份状态在两个地方各存一份**、或**该共享的没共享**。
> 这类 bug 表现为"改了 A 页 B 页没变""切回来数据还是旧的""两个弹窗互相覆盖"，编译期无感知。

每个状态逐一判定，写进设计文档：

| 状态存哪 | 判据 | 典型 |
|---|---|---|
| **组件内部** | 只有这个组件用、卸载即可丢弃 | 弹窗开关、hover、未提交的表单草稿 |
| **父组件下发（props）** | 父子共用，且父是唯一真源 | 选中行、当前筛选条件 |
| **全局 store** | **跨路由**存活，或 ≥2 个互不相邻的组件要读 | 用户信息、全局日期范围、账号切换 |
| **URL query** | 刷新/分享后必须还原 | 筛选条件、分页、tab 页签 |

**硬规则**：

- 🔴 **同一份状态只能有一个真源**，其余地方一律派生。禁止"store 存一份、组件里再 copy 一份"——这是 L7「单一真源」在前端的同款
- **能放 URL 就别放 store**：刷新即丢的筛选条件是高频投诉点
- 全局 store 读写走 `useAppStore` / `useUserStore`，**禁止手动解析 sessionStorage**（见项目 CLAUDE.md Store 约定）
- 用户维度的本地存储 key 必须带 `userid_` 前缀，否则多账号会串数据

## 🔴 边界态四件套（逐组件逐态写，不许笼统一句"有处理"）

Step8 前端矩阵会按这四态逐条验，设计阶段没写的，编码阶段一定没有：

| 态 | 要写明 | 常见漏项 |
|---|---|---|
| **loading** | 骨架屏还是 spinner？占位是否撑住高度？**慢接口会不会闪**？ | 慢接口真实存在（本工作区列表接口实测数十秒，数据见项目 `AGENTS.md`），loading 必须撑住 |
| **空数据** | 首次进入无数据 vs 筛选后无结果，**两者文案不同** | 只做了一种，另一种显示"暂无数据"让用户以为坏了 |
| **错误** | 英文友好文案（见 L16）、能否重试、**不暴露原始 code/堆栈** | 直接渲染 `parseFailReason` |
| **权限不足** | 入口隐藏还是置灰+提示？置灰时 hover 说明原因 | 只做了接口 403，入口照样可点 |

**权限相关（见 L14）**：模板隐藏用 `v-pacvuePermission` 指令，代码判断用 `usePacvuePermission`，
**禁止散落手写 `userRole === "Read"`**，禁止手动解析 `window.permissionObj`。

## 🔴 契约对齐自检（落盘前逐条核）

设计里出现的每个字段，必须能在 Step6 契约中指到：

- [ ] 每个 API 调用的**入参字段**都在契约的请求体里？类型一致？
- [ ] 每个渲染用到的**响应字段**都在契约的响应体里？（禁止"后端应该会返回"）
- [ ] 枚举值取值范围与契约一致？前端有没有自己多写一个状态？
- [ ] 分页结构与契约一致（`pageIndex/pageSize` 还是 `page/size`）？
- [ ] `xxxId` 类字段是否有配对的展示名（见 L3）？没有就回 Step6 补，**不要前端自己查字典**
- [ ] 列表/详情/导出用的是同一套字段口径吗（见 L14 四处口径一致）？

对不上的**不要在前端兜**——回 Step6 改契约并同步后端，否则就是把契约偏差藏进前端代码。

## 组件复用决策（承接 Step4，见 L15）

每个组件必须给出结论，不许留空：

```
| 组件 | 决策 | 依据 |
|---|---|---|
| 筛选区 | 复用 PacvueNewFilter | 项目强制：筛选区必须用它（见 CLAUDE.md） |
| 素材卡片 | 新建 AssetCard | Grep 过 packages/main 无同类；仅本模块用 |
```

- **筛选区一律 `PacvueNewFilter`**，禁止手工拼 `PacvueSelect + PacvueInput + 按钮`
- 组件库优先级：`@pacvue/element-plus` > 项目自研组件 > 原生 `el-*`
- 通用逻辑（日期/金额/时区/防抖/下载/存储/请求/i18n）先查 `pacvue-common-utils`，**禁止重复造轮子**
- 国际化统一裸用全局 `$t("key")`，禁止 `useI18n()`
