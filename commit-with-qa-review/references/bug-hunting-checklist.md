# Bug Hunting Checklist（测试视角）

用法：对 diff 涉及的每个检查域给出结论 —— **发现问题**（附 `文件:行` + 触发输入 + 后果）或 **不适用**（说明为什么）。禁止写「看起来没问题」而不给推演。

---

## A. 通用（所有语言）

### A1 输入边界
- null / undefined / 空字符串 / 空集合 / 空 Map
- 0、负数、最大值溢出、精度丢失（金额、比率、除法）
- 超长字符串、特殊字符、emoji、前后空格
- 重复元素、乱序、单元素集合
- 除零、取模负数、`Math.round` 银行家舍入差异

### A2 空值与解引用
- 链式取值中任一环为 null
- `Optional.get()` / `!` 断言 / `as` 强转
- Map.get 返回 null 后直接用
- 集合 `get(0)` 前没判空

### A3 分支与逻辑
- if/else 是否覆盖全部情况，缺 else 时默认行为是什么
- 布尔取反、`&&`/`||` 短路顺序、德摩根写错
- switch 缺 default / 缺 break
- 早返回是否跳过了必要的清理/落库

### A4 循环与集合
- off-by-one（`<` vs `<=`）
- 循环内做 IO / 查库 / 调远程（N+1）
- 遍历中修改集合
- 提前 break/continue 后状态是否一致

### A5 错误处理
- catch 后吞异常（空 catch、只打 log 不上抛）
- 异常后资源未释放 / 事务未回滚 / 状态半写
- 错误提示文案是否符合规范（本工作区：返回客户端的文案必须英文）
- 超时、重试、幂等：重试会不会造成重复下单/重复落库

### A6 并发与顺序
- 共享可变状态（静态字段、单例成员、缓存）
- 非原子的「读-改-写」
- 多请求同时到达同一条记录 → 覆盖写、丢更新
- 异步任务对上下文（ThreadLocal、事务、用户身份）的依赖

### A7 安全
- SQL 拼接 / 命令拼接 / 路径穿越
- 权限判断是否可被绕过：只在前端判、只判角色不判数据归属
- 敏感信息进日志（token、密码、身份证、手机号）
- 硬编码密钥、测试账号、内网地址

### A8 回归面
- 改了的方法有哪些调用方？`grep` 出来逐个确认语义没变
- 老数据 / 老配置 / 老版本客户端还能跑吗
- 改了公共工具/基类，影响半径有多大
- 删掉的代码真的没人用吗

## B. 后端 Java / Spring Boot

### B1 SQL 与 ORM
- **UPDATE/DELETE 是否一定带 where**；where 条件为空时会不会退化成全表
- `in (...)` 参数为空集合 → 语法错或条件被剔除
- `in (...)` 参数超上限（MSSQL 2100 参数）→ 必须分批
- 索引：新查询条件有没有索引，是否全表扫
- 分页：count 与 list 条件不一致、深分页性能
- 实体字段与列名映射（MyBatis-Plus 下划线转换需要 `@TableField`）
- 逻辑删除字段是否被漏掉
- 多表 join 的数据放大（一对多导致行数翻倍）

### B2 事务
- `@Transactional` 在同类内部调用不生效（自调用走不到代理）
- 事务里调远程/发 MQ/写文件 → 回滚不掉
- 事务范围过大（包住了慢 IO）
- readOnly 里做了写操作

### B3 Spring / 依赖
- 字段注入 vs 构造注入（本工作区 ArchitectureTest 有相关约束）
- Bean 作用域：单例里放请求态数据
- 配置项（Apollo）新增后各 profile 是否都配了，缺失时默认值是什么
- Feign 调用：超时、降级、返回 null、异常透传；测试中必须 mock

### B4 API 契约
- 新增/修改字段是否向后兼容（老前端会不会挂）
- 必填校验、参数默认值
- OpenAPI 注解与接口文档是否同步更新
- 返回结构变化是否通知了调用方

## C. 前端 Vue3 / Pacvue

### C1 响应式
- `ref` / `reactive` 解构丢响应性
- watch 的 deep / immediate 缺失或滥用
- computed 里写副作用
- props 直接修改

### C2 生命周期与泄漏
- 定时器 / 事件监听 / IntersectionObserver 未在 unmount 清理
- 请求返回时组件已卸载 → 赋值到已销毁实例
- 路由切换的竞态（旧请求后返回覆盖新数据）

### C3 渲染
- `v-for` 的 key 用 index 导致错位
- `v-if` / `v-for` 同级
- 大列表无虚拟滚动
- 空数据 / loading / 错误三态是否都有

### C4 Pacvue 专项
- 组件优先级：`@pacvue/element-plus` > 项目自研 > 原生 `el-*`
- 公共方法先查 `pacvue-common-utils`，禁止手写等价实现
- 请求统一走 `@pacvue/frame/request`
- 国际化：裸用全局 `$t("key")`，硬编码中英文文案都算问题
- 存储 key 必须带 `userid_` 前缀（多账号串数据）
- 权限：`v-pacvuePermission` / `usePacvuePermission`，禁止手写 `userRole === "Read"`
- 筛选区必须用 `PacvueNewFilter`
- store 通过 `useStoreModule` 注册，全局日期/账号读 `useAppStore`

---

## D. 数据与迁移

- DDL 变更是否可回滚，是否需要先发后端再发前端
- 新增非空列有没有默认值（老数据会炸）
- 数据刷新脚本的幂等性与批量大小
- 时区：存储用 UTC 还是本地，展示层做没做转换（本工作区涉及 PST）
- 金额/比率的精度与舍入口径是否与其他模块一致

---

## E. 提交卫生

- 调试代码：`System.out.println`、`console.log`、`debugger`、注释掉的旧逻辑
- 临时文件、本地配置、`.log`、构建产物
- TODO / FIXME 留在提交里是否可接受
- 改动是否混进了与本次需求无关的格式化（污染 diff）
- 密钥、token、内网地址、真实客户数据
