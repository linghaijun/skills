# Bug Hunting Checklist（测试视角）

用法：对 diff 涉及的每个检查域给出结论 —— **发现问题**（附 `文件:行` + 触发输入 + 后果）或 **不适用**（说明为什么）。禁止写「看起来没问题」而不给推演。

🔴 **写不出具体触发条件（什么输入 / 时序 / 数据状态）的「问题」不算发现**，删掉，不要凑数 —— 绝大多数是看串了或想当然。见文末「不算发现的」。

> 标 〔fs〕 的条目吸收自 `ai-driven-fullstack-workflow/references/bug-hunting-checklist.md`（2026-10-14 review 对齐；两份各自维护，对方的 `LNN` 编号不跨 skill 引用）。
> 标 〔bl〕 的条目来自项目历史 bug 经验文档（creative-management-all `docs/bug-lessons.md`，编号见括号）。

## A. 通用（所有语言）

### A1 输入边界
- null / undefined / 空字符串 / 空集合 / 空 Map
- 0、负数、最大值溢出、精度丢失（金额、比率、除法）
- 超长字符串、特殊字符、emoji、前后空格
- 重复元素、乱序、单元素集合
- 除零、取模负数、`Math.round` 银行家舍入差异
- 〔fs〕浮点直接比较相等；**金额用了 double**；`int` 装计数会不会溢出
- 〔fs〕`substring` / `charAt` 下标越界；`split` 后把数组长度假设成固定值
- 〔fs〕分页参数：`pageSize=0`、`pageIndex=0` 或负数、`offset` 差 1、`total` 与实际条数不一致
- 〔fs〕时间：区间开 / 闭、跨天 / 跨月 / 跨年、夏令时（时区见 D）
- 〔fs〕枚举收到**不认识的值**时怎么办（抛异常 / 走 default / 静默忽略），哪种是对的

### A2 空值与解引用
- 链式取值中任一环为 null
- `Optional.get()` / `!` 断言 / `as` 强转
- Map.get 返回 null 后直接用
- 集合 `get(0)` 前没判空
- 〔fs〕自动拆箱：`Integer` 参与算术可能 NPE；`Integer == Integer` 比的是引用
- 〔fs〕`getOrDefault` 的默认值与「真实值」有没有语义歧义

### A3 分支与逻辑
- if/else 是否覆盖全部情况，缺 else 时默认行为是什么
- 布尔取反、`&&`/`||` 短路顺序、德摩根写错
- switch 缺 default / 缺 break
- 早返回是否跳过了必要的清理/落库
- 〔fs〕状态机：非法流转拦住了吗（已审核的还能再提交？已删除的还能被引用？）

### A4 循环与集合
- off-by-one（`<` vs `<=`）
- 循环内做 IO / 查库 / 调远程（N+1）；批量接口被逐条调用
- 遍历中修改集合
- 提前 break/continue 后状态是否一致
- 〔fs〕去重用了 `equals` 但没重写 `hashCode`；可变对象做 Map key；`subList` 后仍引用原集合
- 〔fs〕大集合一次性加载进内存（无分页、无流式）
- 〔bl B-01〕**改了去重 / 唯一性口径**（如去重键从 A 改成 A+B）：下游还按旧键建 `Map` / `put` / 注释写着「A 唯一」的地方会后写覆盖先写、静默串槽 —— diff 里改了去重键，就全仓 grep 旧键的 Map

### A5 错误处理
- catch 后吞异常（空 catch、只打 log 不上抛）→ **失败被当成成功**
- 异常后资源未释放 / 事务未回滚 / 状态半写
- 错误提示文案是否符合规范（本工作区：返回客户端的文案必须英文）
- 超时、重试、幂等：重试会不会造成重复下单/重复落库
- 〔fs〕`catch (Exception)` 范围过宽，把本该抛出的业务异常也吃掉；`finally` 里再抛异常覆盖原始异常
- 〔fs〕降级分支把**不同根因塌缩成同一句固定文案** → 故障时分不清「永久失败需人工」与「瞬时抖动会自愈」
- 〔fs〕原始堆栈 / 内部 code / 敏感数据直接返回给前端

### A6 并发与顺序
- 共享可变状态（静态字段、单例成员、缓存、复用的 `SimpleDateFormat`）
- 非原子的「读-改-写」；〔fs〕先查后写（check-then-act）之间的竞态窗口
- 多请求同时到达同一条记录 → 覆盖写、丢更新（〔fs〕有没有乐观锁 `version`）
- 异步任务对上下文（ThreadLocal、事务、用户身份）的依赖；〔fs〕主线程已返回但事务未提交，异步里查不到刚写的数据
- 〔fs〕重复提交 / 重复消费：接口幂等吗？MQ 消息重投会不会产生两条
- 〔bl B-02〕**异步结果落地读的是「当前」状态还是「发起那一刻」的快照**：等待中相关控件没锁、回包没有指纹 / seq 守卫 → 旧请求按新上下文解析（假失败 + 副作用已发生）
- 〔fs〕🔴 **测试代码改静态 / 全局状态**（static mock 开关、单例缓存、系统属性）：JUnit 类级并发时互改 → 随机红 / 随机绿；加 `@ResourceLock("<资源名>")` 或改实例注入（CP-58118 实例）。测试代码问题与业务缺陷分开记，但要修

### A7 安全
- SQL 拼接 / 命令拼接 / 路径穿越
- 权限判断是否可被绕过：只在前端判、只判角色不判数据归属；〔fs〕改一个 id 就能访问别人的数据（水平越权）
- 敏感信息进日志（token、密码、身份证、手机号）
- 硬编码密钥、测试账号、内网地址
- 〔fs〕文件上传：类型与大小校验、路径穿越

### A8 回归面
- 改了的方法有哪些调用方？`grep` 出来逐个确认语义没变
- 老数据 / 老配置 / 老版本客户端还能跑吗；〔fs〕老缓存 / 老消息格式还兼容吗
- 改了公共工具/基类，影响半径有多大
- 删掉的代码真的没人用吗

## B. 后端 Java / Spring Boot

### B1 SQL 与 ORM
- **UPDATE/DELETE 是否一定带 where**；where 条件为空时会不会退化成全表
- `in (...)` 参数为空集合 → 语法错或条件被剔除
- `in (...)` 参数超上限（MSSQL 2100 参数）→ 必须分批
- 索引：新查询条件有没有索引，是否全表扫
- 分页：count 与 list 条件不一致、深分页性能
- 实体字段与列名映射（MyBatis-Plus 下划线转换需要 `@TableField`）
- 逻辑删除字段是否被漏掉 —— 〔fs〕`WHERE` / `JOIN` / `EXISTS` 子查询里**每个**带 `is_delete` 的表都要加
- 多表 join 的数据放大（一对多导致行数翻倍）
- 〔fs〕`${}` 与 `#{}` 用反（注入）；动态 SQL `<if>` 全不满足时变成 `WHERE AND` 或条件全丢
- 〔fs〕数据权限：列表 / 详情 / 导出 / 筛选项**四处口径一致**；`visibleUserIds` 与授权 `profileIds` 都注入了
- 〔fs〕枚举 → DB 存储值：写入侧和读取侧用的是同一个属性；表名 / 字段名与实际 DDL 一致

### B2 事务
- `@Transactional` 在同类内部调用不生效（自调用走不到代理）；〔fs〕加在 private 方法上同样不生效
- 事务里调远程/发 MQ/写文件 → 回滚不掉；〔fs〕先提交再发消息 vs 先发消息再提交，哪侧失败会不一致
- 事务范围过大（包住了慢 IO）
- readOnly 里做了写操作
- 〔fs〕默认只对 `RuntimeException` 回滚，受检异常不回滚

### B3 Spring / 依赖
- 字段注入 vs 构造注入（本工作区 ArchitectureTest 有相关约束）
- Bean 作用域：单例里放请求态数据
- 配置项（Apollo）新增后各 profile 是否都配了，缺失时默认值是什么
- Feign 调用：超时、降级、返回 null、异常透传；测试中必须 mock

### B4 API 契约
- 新增/修改字段是否向后兼容（老前端会不会挂）
- 必填校验、参数默认值；〔fs〕枚举白名单、互斥必填；非法值返回 `fail` 而不是 500
- OpenAPI 注解与接口文档是否同步更新
- 返回结构变化是否通知了调用方
- 〔fs〕`Long` 传给前端是否超 JS 安全整数（精度丢失）；时间字段格式与时区约定

## C. 前端 Vue3 / Pacvue

### C1 响应式
- `ref` / `reactive` 解构丢响应性；〔fs〕对象整体替换丢响应性
- watch 的 deep / immediate 缺失或滥用
- computed 里写副作用
- props 直接修改

### C2 生命周期与泄漏
- 定时器 / 事件监听 / IntersectionObserver / 〔fs〕`AbortController` 未在 unmount 清理
- 请求返回时组件已卸载 → 赋值到已销毁实例
- 路由切换 / 〔fs〕快速切换筛选条件的竞态（先发的后回，覆盖新数据）—— 同类见 A6〔bl B-02〕

### C3 渲染
- `v-for` 的 key 用 index 导致错位
- `v-if` / `v-for` 同级
- 大列表无虚拟滚动
- 空数据 / loading / 错误三态是否都有（〔fs〕加「权限不足」共四态）
- 〔fs〕慢接口：loading 撑不住高度页面跳动；加载中能重复点击
- 〔fs〕表单：未提交草稿丢失；只有前端校验、后端不校验
- 〔fs〕Promise reject 未处理
- 〔fs〕🔴 **CSS 过渡与计时器配合**（进度条「停在 100% 再换图」、动画结束再隐藏 / 卸载）：停留 / 延迟计时要**包含过渡时长**，且过渡时长与计时常量**同源**，否则条没画满就被换掉（CP-58118 Q89 实例）

### C4 Pacvue 专项
- 组件优先级：`@pacvue/element-plus` > 项目自研 > 原生 `el-*`
- 公共方法先查 `pacvue-common-utils`，禁止手写等价实现
- 请求统一走 `@pacvue/frame/request`
- 国际化：裸用全局 `$t("key")`，硬编码中英文文案都算问题
- 存储 key 必须带 `userid_` 前缀（多账号串数据）
- 权限：`v-pacvuePermission` / `usePacvuePermission`，禁止手写 `userRole === "Read"`
- 筛选区必须用 `PacvueNewFilter`
- store 通过 `useStoreModule` 注册，全局日期/账号读 `useAppStore`

## D. 数据与迁移

- DDL 变更是否可回滚，是否需要先发后端再发前端
- 新增非空列有没有默认值（老数据会炸）
- 数据刷新脚本的幂等性与批量大小
- 时区：存储用 UTC 还是本地，展示层做没做转换（本工作区涉及 PST）
- 金额/比率的精度与舍入口径是否与其他模块一致

## E. 提交卫生

- 调试代码：`System.out.println`、`console.log`、`debugger`、注释掉的旧逻辑
- 临时文件、本地配置、`.log`、构建产物
- TODO / FIXME 留在提交里是否可接受
- 改动是否混进了与本次需求无关的格式化（污染 diff）
- 密钥、token、内网地址、真实客户数据

## 不算发现的（避免凑数）〔fs〕

- ❌ 写不出「触发条件 + 后果」的猜测
- ❌ 「建议加个注释」「可以考虑重构」这类无缺陷的风格意见（除非命中 P3 的具体项）
- ❌ 与本次改动无关的历史代码问题 —— 单列「遗留观察」，不进必须修复项
- ❌ 已被冻结基线接受的架构存量违规
- ❌ 单测里的问题当成业务代码缺陷（分开记，但仍要修）
